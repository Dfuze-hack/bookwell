# BookWell

BookWell is a volunteer-run learning-resource site. The public website keeps its original single-page design and adds a catalog interface backed by a Supabase project when configured. It does not include sample products, fake reviews, payment simulations, or production credentials.

## Current implementation

- Original BookWell logo assets, green-and-white colors, Georgia typography, navigation, mission, volunteer information, contact details, and Google Translate UI are preserved.
- Once Supabase is configured, the library supports server-side catalog search, category, free/paid, file-format, selected-currency price-range filters, sorting, pagination, product details, and empty/loading/error/retry states. Prices format from each product's stored ISO currency using `Intl.NumberFormat`; no exchange rates or conversions are used. Price sorts group by currency rather than comparing unlike amounts.
- The Discover section builds subject and language filters from published catalog records, shows actual per-subject listing counts, sorts recently added items by recorded `created_at`, and offers explainable recommendations based on selected subjects, search text, and public listing metadata. It does not use fake popularity, sales, or engagement metrics.
- Optional subject interests and up to eight recently viewed slugs are stored only in the current browser. Recently viewed listings are re-fetched through the public product-detail RPC before rendering, so archived/unpublished items are not trusted from browser storage. Search text is remembered for the current browser session.
- Language filtering, relevance sorting, exact public category/language facets, and related-product results use the new `20261026120000_smart_discovery.sql` migration. The migration returns only published metadata and never returns private product-file paths. The later `20261026180000_paid_product_previews.sql` migration returns the designated public preview path for published free and paid listings without exposing their product files. Neither migration has been applied to a hosted project.
- The follow-up `20261026150000_public_catalogue_creator_fallback.sql` migration makes creator profiles optional for public search, detail, and related-product RPCs. Published administrator-created products remain visible without a profile and use the non-sensitive `BookWell` fallback creator name. Category and language facets remain based on published products in active categories; the migration reasserts the existing anon/authenticated execute grants and adds no new privileges or RLS changes.
- Only published products are returned by database search functions. The commerce migration allows published paid listings to appear in the catalogue/detail pages, but product file paths remain excluded from public SQL reads.
- Published paid products can be displayed with their stored ISO currency and a Buy action. Checkout is intentionally fail-closed: no provider adapter or merchant credentials are configured, so the endpoint refuses purchases and does not create a payment success or entitlement.
- The unapplied commerce migration verifies provider-reported totals against immutable order items, deduplicates provider events, grants purchase entitlements only after verified success, and expires purchase entitlements on partial or full refunds. Any refund status removes download eligibility under the current order rule.
- Free and paid filters, price ranges, sorting, pagination and product details remain server-side. Price ranges still require one selected currency; prices are never converted.
- The existing `currency` and `price_minor` columns support ISO currency-specific minor units without a schema migration: the admin currently offers USD, INR, EUR, GBP, AUD, JPY, and KWD. Amounts are converted using each currency's ISO minor-unit precision (including zero-decimal JPY and three-decimal KWD), and displayed with `Intl.NumberFormat`. Because `price_minor` is a signed 32-bit integer, accepted prices are capped to its representable range for the selected currency. Price filters require a selected currency and compare only values in that currency; no exchange rates or conversions are used.
- USD (`$`) is now the default for marketplace price-range selection and newly created product drafts. Existing listings continue to display their actual stored currency; no foreign-currency amount is relabeled as dollars or converted without an exchange rate.
- The download flow checks the user's authorization through a Supabase Edge Function, then uses the server-only service role to retrieve the private file path and issue a 60-second signed URL. It is unavailable until Supabase is configured and deployed. The commerce migration removes direct client execution of the private-path RPC. The latest entitlement migration keeps free downloads publication-gated while preserving paid or otherwise entitled downloads after a listing is archived or unpublished.
- The migration lays groundwork for roles, creator listings, orders, idempotent payment events, subscription plans and entitlements, saved products, collections, eligible reviews, reports, authorized-download-link history, payout ledgers, payouts, and audit logs. A logged link issuance does not prove that the file transfer completed.
- Administrator sign-in, product CRUD, upload validation, and a local unsaved-listing preview are implemented in the static UI. Supabase Auth and the migration must be configured first. The access token is held in memory only, so an administrator must sign in again after a page reload.
- Creator Studio reuses the administrator product-management backend for overview, product status filters, draft creation/editing, duplication, publication/archive, previews, private uploads, and recorded analytics. Administrators retain full publication control. The unapplied `20261026200000_pdf_book_listings.sql` migration lets the existing `creator` role upload into their own product-id Storage prefix, list only their own products through `admin_list_products`, and edit unpublished listings they own. Creators still cannot publish, archive published books, delete listings, assign roles, or write into another creator's Storage folder.
- The commerce migration adds an optional product `language` field without fabricating values for existing listings, and returns it through public listing/detail and admin product RPCs. Product type reuses the existing supported `formats` array; covers reuse the existing private preview-image bucket.
- Creator Studio analytics count exact stored product states, download-link issuance events (not completed downloads), and paid orders with a verification timestamp. Product page views and revenue are not currently tracked.
- The account area now uses the pinned Supabase JavaScript v2 client for email/password sign-up and sign-in, confirmation/resend, password recovery with invalid/expired-link handling, persistent PKCE sessions, sign-out, private display-name settings, saved products, and a personal library split into My Purchases, Free Downloads, and Other Access. Recovery redirects include an explicit allowlisted marker because the pinned PKCE client may complete the code exchange as a normal session; the UI requires an authenticated session before showing the new-password form. The Library remains public to browse.
- Saved-product relationships and private profiles are scoped to the authenticated user by RLS. The personal library sections are returned by authenticated database functions that call the existing `can_download_product` authorization rule. My Purchases is derived from verified paid order items and remains separate from the free catalogue, so a large free collection cannot hide purchases. Free Downloads excludes products with a current verified purchase to keep the three sections distinct, and Other Access preserves admin-grant, premium-subscription, and creator/admin access without duplicating free or purchased rows. Each section uses deterministic newest-first ordering with a product-ID tie-breaker and cursor pagination, defaults to 24 rows, and requests 25 rows to detect whether another page exists. Paid access is still not purchasable; only legitimate free access and any existing server-managed entitlement/order records can authorize downloads. Entitled purchasers keep their library entry and file access when a listing is archived or unpublished, while archived free listings remain unavailable.
- Public catalogue cards use the authenticated account's server-backed library state to show `In your library` and a Download action for accessible products. Paid products that are not accessible show Buy only after the access check completes; signed-out visitors see a sign-in action, and loading or access failures fail closed without offering a purchase. Ownership is not inferred from localStorage, a browser-supplied user ID, or order rows alone.
- Purchase history offers a direct Download action only when a provider-verified completed order item matches a product in the loaded My Purchases pages. The action reuses `create-download`, which rechecks authorization and issues a short-lived signed URL; pending, failed, cancelled, refunded, or no-longer-accessible orders do not offer a direct download. If a verified order is older than the loaded purchase pages, the row asks the user to load more purchases before confirming access. Entitled archived products remain downloadable from both My Purchases and purchase history, while refunded and unowned products remain blocked by the server.
- The `20261025204000_user_accounts.sql` migration adds a minimal private `user_profiles` table, its RLS/grants, a user-scoped recent-download index, and the legacy `list_my_library_products()` function. The legacy function is retained for migration compatibility but is no longer called by the frontend. The migration reuses the existing `saved_products`, `entitlements`, and download authorization schema. It has not been applied to any Supabase project.
- The follow-up `20261026160000_preserve_purchased_product_access.sql` migration separates public visibility from download authorization. Free access still requires a published listing in an active category, creator/admin access remains publication-gated, and existing paid-order, active admin-grant, or active premium-subscription entitlements can authorize a private file after the listing is archived or unpublished. It does not change public catalogue or purchase RPCs, RLS table policies, or Storage bucket visibility, and it has not been applied to any Supabase project.
- The new `20261026170000_paginated_library_sections.sql` migration adds three authenticated, cursor-paginated RPCs: `list_my_purchase_products`, `list_my_free_downloads`, and `list_my_additional_access_products`. Purchases require a verified `paid` order with an unrefunded line item and current server-side download access; pending, failed, cancelled, refunded, and fully refunded items are excluded. Free downloads require a published zero-price listing in an active category and exclude purchased rows, while Other Access covers remaining authorized products. All three derive the user only from `auth.uid()`, validate paired cursors, clamp page size, return no private file paths, and grant execute only to `authenticated`. The migration also adds ordering indexes for product creation and verified paid orders. It has not been applied to any Supabase project.
- The unapplied `20261026190000_inactive_category_public_access.sql` migration defines one public-eligibility rule: a product is public only when it is `published` and its category is active. It applies that rule to direct `products` RLS, public product reviews, creator-profile visibility, and free download authorization. Products and free files in inactive categories are hidden, while valid paid orders, active admin grants, and active premium subscriptions still authorize already-purchased files after archive/unpublish or category deactivation. It does not change payment behavior or make either Storage bucket public.
- Supabase sessions are persisted and refreshed by the Supabase JS client in browser storage. This is standard for the client SDK; use HTTPS, the public anon key only, configure trusted redirect URLs, and never store passwords in BookWell code.
- Product previews are in a private Storage bucket. Anonymous users can create a five-minute signed preview URL only when the database row and Storage RLS confirm that the object is the current `preview_path` of a published product in an active category; free and paid listings follow the same publication rule. Draft/unpublished previews are not readable through public object URLs or signed-URL requests. A preview is a public catalogue asset, while the paid product file remains private and requires `create-download` authorization. The same active-category publication rule applies to direct public product rows, public reviews, creator-profile visibility, and anonymous free-file authorization.
- Administrator file uploads perform size, extension, and signature checks in the browser; Supabase Storage also enforces bucket MIME metadata and size limits. This does not provide antivirus scanning or comprehensive archive/document validation.
- Optional book metadata (author, subtitle, publication year, edition, ISBN, page count) is stored on the existing `products` table and returned by public catalogue/detail/related RPCs without exposing `file_path`. PDF validation checks extension, declared MIME type when present, `%PDF-` signature, emptiness, and the existing 50 MB product-files bucket limit.
- No in-browser PDF reader, provider-specific checkout adapter, live or sandbox payment integration, subscription activation, upload malware scanner, or payout workflow is implemented. No payment credentials have been added.

## Local development

This repository has no Node build or dependency installation. Serve the static site from the repository root:

```powershell
python -m http.server 8000
```

Open `http://localhost:8000`. Without a configured Supabase project, the website preserves its public content and displays a clear catalogue setup state; the admin interface remains disabled and the catalogue does not show invented products.

For a local Supabase CLI project, use its local API URL (typically `http://127.0.0.1:54321`) and local anon key in `supabase-config.js`. Browser configuration accepts only an HTTPS `*.supabase.co` project URL or the local loopback API on port `54321`; it rejects arbitrary HTTP hosts.

For local Edge Function development, install the Supabase CLI and Docker, then follow Supabase's local development instructions. Email/password accounts are implemented in the frontend but still require a real configured Supabase project. The checkout and webhook function boundaries remain disabled until a provider adapter and eligible merchant account are configured. Do not test paid access by editing browser storage.

### Safe reset

- Use only disposable test records and synthetic files.
- To reset local Supabase, verify no hosted project is linked for the command and use the local CLI's `supabase db reset` only against the local container.
- To discard a disposable hosted test environment, verify its project name/ref in the Dashboard, export only non-sensitive test results if needed, then delete that disposable project in the Dashboard. Do not run reset/drop/truncate commands against production or an unverified linked ref.
